# NRI AIエージェントナレッジシステム - プロジェクト憲章

**バージョン**: 1.0.1
**批准日**: 2025-10-27
**最終改正日**: 2025-10-27
**プロジェクト**: AIエージェント駆動型ナレッジカードシステム PoC
**状態**: 有効

---

## 前文

本憲章は、AIエージェント駆動型ナレッジカードシステムPoC（以下「本プロジェクト」）における開発原則、品質基準、および運用方針を定めるものである。

本プロジェクトは、AIエージェント利用の副産物として社内ナレッジを自動カード化し、反例警告つきで安全に共同利用できる基盤を実証することを目的とする。

すべての開発活動は本憲章に定める原則に従わなければならない（MUST）。

---

## 1. 目的と適用範囲

### 1.1 目的
AIエージェント利用の副産物として社内ナレッジを自動カード化し、反例警告つきで安全に共同利用できる基盤を実証する。

### 1.2 適用範囲
本憲章は以下に適用される：
- 本PoCで作成されるすべてのコード
- 設定ファイルおよびデータスキーマ
- 評価スクリプトおよびテストコード
- ドキュメンテーション一式

### 1.3 適用外
以下はPoCの範囲外であり、本憲章の対象外とする：
- 本番級監視システム
- 厳密なRBAC（ロールベース・アクセス制御）
- 多段グラフ探索（1-hopを超える探索）
- 高機密データの取り扱い

**根拠**: PoCフェーズでは技術的実現可能性とアーキテクチャの妥当性検証に注力し、本番運用に必要な機能は将来フェーズで対応する。

## 2. アーキテクチャ原則

### 2.1 最小公開インターフェース
**必須（MUST）**: 公開インターフェースは以下の2つのみとする：
- `Tool: store_knowledge` - ナレッジ蓄積
- `Resource: knowledge://search` - ナレッジ検索

**根拠**: インターフェースを最小化することで、システムの複雑性を抑え、保守性と安全性を確保する。

### 2.2 ハイブリッド検索アーキテクチャ
**必須（MUST）**: 検索は以下の3段階で実行する：
1. Vector Search ∪ BM25 Search（ベクトル検索と全文検索の統合）
2. 1-hop Graph Expansion（:SUPPORTS / :CONTRADICTS による1段階グラフ拡張）
3. Re-ranking with weighted scoring（重み付けスコアによる再ランク）

**根拠**: 複数の検索手法を組み合わせることで、精度（Recall@10 ≥ 0.6）と関連性を両立する。

### 2.3 ローカル埋め込み既定
**必須（MUST）**: 埋め込みはローカル（オンプレミス）で実施する。
**必須（MUST）**: 使用モデルと次元数を各Cardに記録し、再現性を担保する。

**記録フィールド**:
- `embedding_model`: 使用モデル名（例: "multilingual-e5-base"）
- `embedding_dim`: ベクトル次元数

**根拠**: オンプレミス運用を前提とし、外部APIへの依存を排除。モデル情報の記録により、将来のモデル変更時の影響分析と移行が可能。

### 2.4 1-hop限定グラフ
**必須（MUST）**: グラフ関係は1-hop限定とする。
**必須（MUST）**: 自動推定された関係は `:CANDIDATE_SUPPORTS` / `:CANDIDATE_CONTRADICTS` として格納する。
**推奨（SHOULD）**: 人手による確認後、確定関係 `:SUPPORTS` / `:CONTRADICTS` に昇格する。

**根拠**: PoCでは深い推論を避け、シンプルで検証可能な関係性に限定。候補関係の導入により、自動化と品質のバランスを取る。

### 2.5 冪等性
**必須（MUST）**: `content_hash` によるUpsertを実装し、同一内容の重複登録を防止する。
**必須（MUST）**: Embedding Cacheを必須とし、計算コストを削減する。

**根拠**: 重複データの防止とパフォーマンス最適化。

### 2.6 安全性優先
**必須（MUST）**: 反例（:CONTRADICTS関係）が存在する場合、必ず `warnings[]` を返す。
**必須（MUST）**: 警告には要約と `card_id` を含める。

**根拠**: "安全な再利用"を最優先とし、誤った情報の適用を防止する。

## 3. データと知識品質

### 3.1 カード必須フィールド
**必須（MUST）**: すべてのCardは以下のフィールドを持つ：

**コアフィールド**:
- `id`: 一意識別子
- `title`: カードタイトル
- `type`: 'lesson'|'guideline'|'pitfall'|'case-study'|'faq'
- `situation`: 状況説明
- `action`: 実施した行動
- `outcome`: 結果

**コンテキストフィールド**:
- `applicability`: 適用可能条件（配列）
- `anti_applicability`: 適用不可条件（オプション、配列）
- `scope`: 'personal'|'team'|'org'
- `tags`: タグ配列（オプション）

**品質フィールド**:
- `quality`: 'draft'|'verified'（デフォルト: 'draft'）
- `visibility`: 'public'|'restricted'（デフォルト: 'restricted'）

**技術フィールド**:
- `embedding`: ベクトル表現
- `embedding_model`: 使用モデル名
- `embedding_dim`: ベクトル次元数
- `content_hash`: SHA256ハッシュ
- `created_at`, `updated_at`, `version`

**根拠**: 構造化されたスキーマにより、一貫性のあるデータ管理と高精度な検索を実現。

### 3.2 品質レベル
**必須（MUST）**: 新規Cardは `quality: draft` で登録する。
**推奨（SHOULD）**: 人手確認後に `quality: verified` に昇格する。

**根拠**: 自動生成コンテンツと人手検証済みコンテンツを区別し、信頼性を明示。

### 3.3 個人情報マスク
**必須（MUST）**: 保存前に以下の個人情報（PII）を簡易マスクする：
- メールアドレス
- 電話番号
- 住所
- 社員ID
- その他識別可能な個人情報

**必須（MUST）**: 原文は保持せず、マスク後のテキストのみを保存する。

**根拠**: プライバシー保護と法規制遵守。

### 3.4 タグ語彙管理
**必須（MUST）**: タグは以下のルールで正規化する：
- 小文字化
- ハイフン統一（アンダースコア → ハイフン）
- 辞書化（例: "perf", "cdn", "spa", "security", "performance"）

**根拠**: タグの一貫性を保ち、検索精度を向上。

## 4. 自動蓄積の原則

### 4.1 フック対象
**必須（MUST）**: 以下のイベントで自動カード化を検討する：
- タスク完了
- 成果確定
- エラー解決
- 既存知識の再利用

**根拠**: AIエージェントの自然な利用フローに組み込み、ユーザーの負担なくナレッジを蓄積。

### 4.2 登録判定基準
**必須（MUST）**: 以下のすべてを満たす場合のみ自動登録する：
- 文字数 ≥ 400 文字 OR 見出し ≥ 3
- 具体性（固有名詞/数値 ≥ 5%）
- 重複なし（7日以内の同一 `content_hash` が存在しない）
- 機密語を含まない

**根拠**: 低品質・重複・機密情報の登録を防止。

### 4.3 既定値
**必須（MUST）**: 自動登録時は以下の既定値を使用する：
- `scope`: "team"
- `visibility`: "restricted"
- `quality`: "draft"

**必須（MUST）**: 1ユーザーあたり1日最大3カードに制限する。

**根拠**: 過度な自動登録によるノイズを防止し、適切なスコープで共有。

### 4.4 プッシュ型アーキテクチャ
**必須（MUST）**: エージェント側でテキスト化し、Toolへプッシュする。
**禁止（MUST NOT）**: サーバ側から取りに行く（Pull）方式は使用しない。

**根拠**: エージェントが情報を制御し、サーバは受動的に処理することで、セキュリティとシンプル性を確保。

## 5. 検索スコアとフィルタ

### 5.1 再ランク式
**必須（MUST）**: スコア計算式は以下とする：
```
score = W_SIM × similarity
      + W_FIT × fit_score
      + W_SUP × support_strength
      - W_CON × contradict_strength
```

**既定重み**:
- `W_SIM`: 0.5（類似度）
- `W_FIT`: 0.25（適用条件一致度）
- `W_SUP`: 0.15（支持関係）
- `W_CON`: 0.10（矛盾関係）

**必須（MUST）**: すべての重みは環境変数で調整可能とする。

**根拠**: 複数の要因を統合し、最も関連性の高いCardを上位表示。重み調整により、用途に応じた最適化が可能。

### 5.2 表示閾値
**必須（MUST）**: 以下の閾値を適用する：
- `score < 0.4`: 非表示
- `0.4 ≤ score < 0.6`: `low_confidence: true` を付与して表示
- `score ≥ 0.6`: 通常表示

**根拠**: 低品質結果を排除し、中程度の結果には注意喚起を表示。

### 5.3 早期フィルタ
**必須（MUST）**: 以下の条件で早期フィルタリングを実施する：
- `scope`: 'personal'|'team'|'org'
- `tags`: タグ一致
- `type`: カードタイプ
- `quality`: 'draft'|'verified'
- `visibility`: 'public'|'restricted'
- `locale`: 言語コード

**根拠**: 計算コストの高い再ランク前に無関係なCardを除外。

### 5.4 反例警告
**必須（MUST）**: `:CONTRADICTS` 関係が存在する場合、以下を出力する：
- `warnings[]` 配列に要約を含める
- 矛盾する `card_id` を明示する

**根拠**: 矛盾する情報を明示し、誤適用を防止。

## 6. 非機能原則

### 6.1 性能目標
**必須（MUST）**: 以下の性能目標を達成する：

| 指標 | 目標値 |
|------|--------|
| p95応答時間（初回） | ≤ 1.5s |
| p95応答時間（キャッシュヒット） | ≤ 0.8s |
| 同時処理耐性 | 10並列で安定動作 |
| 抽出必須フィールド充足率 | ≥ 95% |
| type推定 F1スコア | ≥ 0.8 |
| 検索 Recall@10 | ≥ 0.6 |
| 反例警告提示率 | ≥ 80% |

**根拠**: ユーザー体験を損なわない応答速度と、実用的な精度を確保。

### 6.2 可観測性
**必須（MUST）**: JSON Lines形式の構造化ログを出力する。
**必須（MUST）**: 以下のフィールドを含める：
- `ts`: タイムスタンプ（ISO8601）
- `req_id`: リクエストID
- `actor_id`: ユーザーID
- `op`: 操作種別（'store'|'search'）
- `elapsed_ms`: 処理時間（ミリ秒）
- `model`: 使用モデル
- `weights`: スコア重み（W_SIM, W_FIT, W_SUP, W_CON）
- `version`: アプリケーションバージョン
- `content_hash`: コンテンツハッシュ
- `auto_capture`: 自動登録フラグ

**根拠**: デバッグ、性能分析、再現性確保のために詳細なログが必須。

### 6.3 フォールバック戦略
**必須（MUST）**: クエリ埋め込み生成が失敗した場合、BM25単独で検索を継続する。
**必須（MUST）**: 既存Cardは検索可能状態を維持する。

**根拠**: 部分的障害時でもサービス継続性を確保。

## 8. 構成と可変性

### 8.1 環境変数
**必須（MUST）**: すべての設定値を環境変数で外部化する：

**埋め込み設定**:
- `EMBED_MODEL`: 埋め込みモデル名

- `EMBED_ENDPOINT`: エンドポイントURL

- `SEARCH_W_FIT`: 適用条件重み
- `SEARCH_W_SUP`: 支持関係重み

**根拠**: 設定変更による品質劣化を防止。

## 12. 用語集

### 12.1 コア用語

**カード（Card）**:
標準スキーマを持つ知識オブジェクト。situation, action, outcome等のフィールドを含む構造化データ。

**候補関係（CANDIDATE_*）**:
自動推定された関係。人手昇格により確定関係（SUPPORTS/CONTRADICTS）となる。

**適用条件一致度（Fit）**:
`applicability` / `anti_applicability` とクエリ条件の一致度を数値化したスコア。

**コンテンツハッシュ（content_hash）**:
Card内容のSHA256ハッシュ。重複検出とIdempotency確保に使用。

**ハイブリッド検索（Hybrid Search）**:
Vector Search、BM25、1-hop Graph Expansionを組み合わせた検索手法。

**1-hopグラフ（1-hop Graph）**:
ある頂点から直接接続された隣接頂点のみを探索する限定的なグラフ探索。

**再ランク（Re-ranking）**:
初期検索結果に対し、複数の要因（similarity, fit, support, contradict）を考慮して順位を再計算する処理。

## ガバナンス

### 改正手順
本憲章の改正は以下の手順で行う：
1. 改正案を `/speckit.constitution` で起案
2. 変更内容を同期影響レポート（Sync Impact Report）で明示
3. 影響を受けるテンプレート・ドキュメントを更新
4. バージョン番号を適切にインクリメント
5. コミットメッセージに改正内容を明記

### バージョニングポリシー
セマンティックバージョニング（MAJOR.MINOR.PATCH）を採用：
- **MAJOR（メジャー）**: 後方互換性のない原則の削除・再定義
- **MINOR（マイナー）**: 新原則の追加、セクションの大幅拡張
- **PATCH（パッチ）**: 明確化、表現の改善、誤字修正

### コンプライアンスレビュー
- すべての開発活動は本憲章への準拠が必要
- プルリクエストレビュー時に憲章違反をチェック
- 四半期ごとに憲章の有効性を評価
